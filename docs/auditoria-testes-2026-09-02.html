Lacunas prioritárias (P0–P2)

P0 pgTAP Supabase — RLS, MFA AAL2, recovery codes

Quatro arquivos em supabase/tests/ (rls_policies, quota_enforcement, mfa_aal2, mfa_recovery) existem mas não rodaram (supabase test db exige Docker). Migrations MFA aplicadas em prod sem prova automatizada local.

P1 OCR de comprovantes (js/ocr.js)

Nenhum teste de parsing, fallback ou integração com formulário. Apenas presença em lazy-chunks.test.js. Risco alto para regressão silenciosa em feature visível ao usuário.

P1 Auth runtime — login Supabase, MFA TOTP, biometria nativa

auth-fase3, auth-hardening e similares são estáticos (leitura de fonte). E2E real skip sem E2E_SUPABASE=1. Plugin Capacitor biometria e FpSecureScreenPlugin sem teste de integração.

P1 Sync Supabase em runtime (supabase-sync.js)

sync-engine, sync-merge e sync-dados cobrem merge e fila, mas o adapter Supabase (push/pull, conflitos, quota) não tem teste de integração com mock de API.

P2 Dois testes falhando (drift de produto)

  • password-policy.test.js — espera abcdefg! válida; política HIBP local barra senhas conhecidas (comportamento correto pós-hardening).
  • marca-nomes-persistidos.test.js — tagline removida do index.html mas ainda exigida no teste.

P2 Camada UI global (~97% de js/ fora dos pisos)

jest.frontend.config.cjs documenta cobertura global honesta (~2,8% linhas na UI). Módulos de negócio têm pisos altos; renderers e init-* dependem de testes estáticos e E2E limitados.
